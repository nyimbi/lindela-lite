# Audit 2026-10

A second audit, commissioned after the first (`docs/improvements/`) had been
implemented. The first asked whether the platform is honest and whether its claims
work. This one asks two different questions:

- **What can it not yet do?** — fifty non-incremental enhancements (`ENH-31..80`).
- **What is wrong right now?** — sixty-eight defects across eight domains.

or a *new* capability, never a restatement. The three new domains — concurrency,
scalability, observability — were named in this audit's brief and were not covered
by the first.

## How to read the severity

- **CRITICAL** — a silent wrong answer, or credential / internal-network exposure.
- **HIGH** — wrong or lost data, or an outage class.
- **MEDIUM** — degraded behaviour, real but bounded.
- **LOW** — latent, or cosmetic with teeth.

## The three findings that matter most

**VUL-01 — the distribution SSRF.** `POST /api/v1/reports/<id>/distribute` fetches
`channel.url` from the request body with no guard (`src/server.js:2909`), while the
webhook path has had `assertSafeWebhookUrl` since the first audit. The guarded twin
exists; this is the copy that never got it. A reports-scope token can reach the
cloud metadata endpoint and the internal network.

**VER-01 — the flood score tracks station density, not rainfall.** Precipitation is
summed across every station within 125 km (`src/analytics.js:452`), so a district
with five stations scores 3× a district with one for the same storm. A coordinator
pre-positions assets where the instruments are, not where the water is. This is the
sharpest instance of a class — a nullable or non-additive field treated as a plain
number — that VER-02 and VER-12 also belong to.

**ARC-01 — the 1,597-line god function.** `handleApiRequestInContext`
(`src/server.js:763–2360`) is the whole API surface. Every substrate enhancement
(streaming reads, request ids, per-server state, a route seam) is harder to land
because there is no seam to land it in. It is the highest-leverage refactor in the
set, and the reason ENH-59/60 sit at the front of the roadmap.

## What this audit did not find

The platform's core discipline holds, and the defects above stand out precisely
because it does. The store layer is a real seam with a conformance suite across both
adapters. Auth is deny-by-default. The webhook SSRF guard is thorough. `narrator.js`
refuses any sentence whose digit is not in its fact set. `numericOrNull` centralises
the absent-value gate and the DEM void rule makes nodata `NaN`, never zero. Metric
cardinality is bounded. These are not incidental; they are why the wrong answers
below are findable at all.

## Method

Four domain audits ran in parallel (concurrency + scalability; observability +
security; data veracity; architecture + maintainability + capability gaps). Every
`file:line` in `defects.md` was re-verified against the tree at `72a6b63` — where an
audit note's line had drifted, the verified line is used. The enhancements are the
author's synthesis over the same evidence.

One defect in this audit is the audit's own instrument: `docs/improvements/status.md`
was generated by a script whose prose was a string literal, so it reported a
shipped/partial state that the tree contradicted. That is fixed and guarded
(`docs/improvements/_build-status.mjs`, `test/enhancement-status.test.js`) and is
recorded here as the cautionary case for any check that reports without measuring.
